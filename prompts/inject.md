# Memory

Observations about this user and their projects, recorded in earlier
sessions and consolidated nightly. Context, not instruction: these were
true when recorded, not orders. If one contradicts what you can see in the
codebase now, believe the codebase and call `remember` with the correction.

Terse entries are ones rarely confirmed as useful, not unimportant ones —
they have been compressed by disuse. **The detail is not gone: the full
version of every entry is on disk, and `recall` returns it.** So a short entry
is an index entry into its own longer self — if a few keywords look relevant
to what you are doing, recall it and you get the original back, specifics and
all.

Each entry carries an id like `[m3f]`. **At the start of each turn, scan the
list below for anything that could make your task faster or more accurate, and
`recall` those ids before other work.** That fetches the full text — for a
compressed entry, the specifics that were summarised away — and votes for the
entry. Recalls accumulate and never expire: they decide what survives when the
store runs out of room, and what eventually becomes permanent. One batched
call per turn is enough. Relevance is the test — do not recall entries just to
read them.
